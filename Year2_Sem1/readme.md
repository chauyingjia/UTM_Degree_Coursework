## 🗂 <ins><a href="https://github.com/chauyingjia/UTM_Degree_Coursework/tree/main/Year2_Sem1/DATA%20STRUCTURE%20AND%20ALGORITHM">Data Structure and Algorithm</a></ins>

### Course Overview

This course is about understanding how to organise and manipulate data efficiently. We covered core data structures like arrays, linked lists, stacks, queues, trees, and graphs, along with the algorithms that work with them. For example, sorting, searching, and traversal. A lot of the focus was on analysing how fast or slow an algorithm is using Big O notation.

### Reflection

This was one of the harder courses in Year 2 but also one of the most rewarding. Before this, I never thought much about whether my code was efficient, I just cared if it worked. Learning about time and space complexity changed that. I started thinking about trade-offs and asking whether there is a better way to solve the same problem. These habits have made me a noticeably better programmer.

## 🗄 <ins><a href="https://github.com/chauyingjia/UTM_Degree_Coursework/tree/main/Year2_Sem1/DATABASE">Database</a></ins>

### Course Overview

This course covers the fundamentals of database systems. We learned how to design a database from scratch using entity-relationship diagrams, how to normalise tables to avoid redundancy, and how to write SQL queries to store, retrieve, and manage data. We also touched on transactions and basic database administration.

### Reflection

Database was one of the most practical courses I have taken so far. SQL felt straightforward to pick up, but the real learning came from database design — figuring out how to structure tables properly so that data stays consistent and queries stay fast. As someone in data engineering, this course sits right at the core of what I will be doing long-term. I use what I learned here almost every week in other projects.

## ⚙️ <ins><a href="https://github.com/chauyingjia/UTM_Degree_Coursework/tree/main/Year2_Sem1/SOFTWARE%20ENGINEERING">Software Engineering</a></ins>

### Course Overview

Software Engineering is less about writing code and more about the process around it. We studied software development life cycles, requirements engineering, project planning, testing strategies, and documentation. The goal is to understand how real software projects are managed from start to finish.

### Reflection

I used to think software engineering was just another name for programming. This course showed me it is really about discipline and communication. A lot of software fails not because the code is bad but because the planning was poor or the requirements were misunderstood. Learning to write proper documentation and think about testing early on has changed how I approach every group project since.

## 🔧 <ins><a href="https://github.com/chauyingjia/UTM_Degree_Coursework/tree/main/Year2_Sem1/SYSTEM%20DEVELOPMENT%20TECHNOLOGY">System Development Technology</a></ins>

### Course Overview

This course focuses on the practical side of building systems. We explored different development methodologies, tools, and technologies used in real-world system development. It bridges the gap between theory and actual implementation, covering how developers work together to deliver a working system.

### Reflection

System Development Technology was the course that felt most like a preview of industry work. We had to actually go through the motions of building something as a team planning, dividing tasks, developing work, and handling things when they did not go as expected. It taught me that building software is a team effort and that coordination matters just as much as technical skill.

---

## 📝 Overall Reflection

Year 2 Semester 1 was a turning point. The subjects were harder, the projects were bigger, and the expectations were higher. But it was also the semester where I started to feel more interested about my direction in data engineering. Databases, algorithms, and system development are not just course topics, they are the building blocks of almost everything in this field. I came out of this semester with a much stronger technical base and a better sense of how to work on complex problems without getting overwhelmed.
